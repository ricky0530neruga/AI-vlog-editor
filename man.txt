AI Vlog Maker V4.4.2 操作手冊（繁體中文）
========================================

一、V4.4.2 修正摘要
V4.4.1 的「候選片段」只讀取 AI 分析成功（v2=1）的資料。
如果某些片段尚未完成評分、模型回傳錯誤、或在 CPU 預篩時被跳過，
它們雖然已經存在 SQLite，卻不會顯示在 GUI，可能造成整頁空白。

V4.4.2 修正：
- 只要完成素材掃描，就建立候選片段資料（不需等待 Ollama 完成）。
- ②挑選片段頁會顯示所有候選及狀態：已分析、未分析、預篩跳過、分析失敗。
- 顯示已索引素材數量、候選總數、AI 完成數、預篩跳過數、分析失敗數。
- 可用狀態篩選、檔名搜尋；點選鏡頭可看縮圖、AI 說明或失敗原因。
- 已跳過／未評分的候選也可「手動加入片單」並輸出；分數僅暫定為中性值50，
  不會寫回資料庫，也不代表它經過 AI 審查。
- 若改過素材來源、導致工作區識別碼不同，可以點「選擇既有分析工作區」
  找到過去的 AI_Vlog_... 資料夾（裡面須包含 index.sqlite）。
- AI 分析全部失敗時，現在會顯示警告，而非宣稱所有素材成功分析。
- 若分析階段意外失敗，仍可保留已掃描的候選素材供手動挑選。

二、更新方式（只替換四個檔案）
1. 先在 Antigravity 對目前 V4.4.1 專案 Commit，或備份你自訂的 GUI 文字。
2. 將本 PATCH 解壓後的 vlog_gui.py、vlog_maker.py、man.txt 覆蓋到專案根目錄。
3. 新增 CHANGELOG_V4_4_2.txt。
4. 其他檔案（cinematic_editor.py、app.py、start_gui.bat、安裝與打包腳本）不變。
5. 原始照片、影片及 Vlogwork/index.sqlite 都不需移動或刪除。
6. 使用 Python 模式可直接雙擊原本 start_gui.bat；若使用 EXE，需重新打包。

三、操作流程
① 掃描與 AI 分析
- 加入一個或多個素材資料夾／檔案，選好輸出根目錄。
- 按「① 開始掃描並分析」。完成後自動切換到②。
- 即使 Ollama 分析失敗，候選鏡頭也應出現在②（狀態會標示原因）。

② 挑選片段 → 剪輯輸出
- 左側預設「全部」，會列出所有候選；可依狀態篩選或搜尋檔名。
- 點選候選顯示靜態縮圖和 AI 評分／錯誤原因。
- 將想保留的片段加入右側片單，使用上移／下移調整順序。
- 未評分的片段可手動選入，但不會憑空獲得 AI 描述或 AI 評分。
- 確認片單、片長、音樂後按「② 按選定片單開始剪輯輸出 MP4」。
- 程式只使用你選定的片段，不會偷偷更換為其他 AI 推薦片段。
- 輸出位置：工作區中的 Travel_Vlog_Final_V43.mp4（沿用 V4.3 渲染引擎命名）。

③ 執行紀錄
- AI 完成 0 個又看到「分析失敗」時，查看 [FAST ERROR]／[REVIEW ERROR]。
- 100% CPU 上執行 Gemma 12B 可能很慢；建議使用平衡+CPU 省時。

四、找不到上次分析資料時
正常工作區位置：輸出根目錄\AI_Vlog_<12碼識別值>\index.sqlite
系統依據「選取的素材來源清單」產生識別碼：更換資料夾路徑、加入單一檔案，
或修改輸出根目錄，都可能切換到另一個工作區。
此時在②按「選擇既有分析工作區」並指向含 index.sqlite 的資料夾即可復用。
重新開始①掃描時，會依當前選取的素材來源使用其正常工作區，避免混淆資料。

五、必要的軟體與環境
- Windows 10/11、Python 3.10+（直接執行 .py 時）；通常內建 Tkinter。
- FFmpeg 與 FFprobe；可安裝於 PATH 或放在專案 tools 資料夾。
- Ollama 服務與視覺模型：gemma3:4b（平衡初選）、gemma3:12b（複審）。
- 原始素材永遠只讀取；index.sqlite、縮圖和輸出影片寫入工作區。
- 影片播放預覽仍由縮圖與清單提供，尚未加入內嵌播放器。

六、Git 增量更新

       git push -u origin fix/v4.4.2-candidates

七、驗證情況
已通過 Python 3.10 語法相容性檢查、SQLite 四種候選狀態檢查、
Linux 虛擬顯示器中的 Tkinter 操作測試、手動加入未評分片段，
以及由該片單實際輸出 1920×1080 MP4 的 FFmpeg 測試。
